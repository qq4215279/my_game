# 游戏服务器

## 游戏进程

### 游戏服务中心 - service_certer 

 HTTP服务器（无状态）

**作用**：

1. 客户端获取网关地址（指定策略）
2. 用户登录，访问第三方地址登录，获取token
3. 客户端充值回调
   1. 客户端第三方支付成功后，回调通知游戏服务器发货(callback/pay)
4. ...



### 网关服 - gateway

客户端与网关建议长连接。

作用：

1. 请求转发/路由（各个游戏服务器）
2. 权限校验，保证请求合法                        吗               
3. 负载均衡
4. 流量控制
5. 玩家心跳管理
6. 消息幂等处理



### 中心服 - center

全局唯一

作用：

1. 排行榜结算发奖
2. 活动结算处理



### 大厅服 - world

游戏核心玩法以外，外围操作。



### 游戏服 - game

核心玩法服务器。

当玩家选择指定玩法时，记录玩家所选择的游戏服信息。

### 聊天消息服 - im

作用

1. 全局聊天
2. 好友系统



## 数据层

技术：JVM + Redis + MongoDB

1. JVM：缓存
2. Redis：建立2级缓存
3. MongoDB：持久化数据

**数据操作流程**：

1. 定义数据类实体，配置表操作信息
2. 创建操作实体管理器
3. 业务中 CRUD 数据实体。
4. 数据线程池，异步写入到数据库中。

**分布式数据一致性处理**：

核心思路：**最终一致性**

1. 核心原则：指定的表隶属于指定游戏服务器
   1. 如果是玩家表，仅限玩家所在游戏服才能写入数据。
   2. 如果是公共表，如公会表，通过分布式锁操作数据。
2. 别的游戏服服务器默认可以读取表数据。数据变更通过redis发布订阅机制，主服通知从服刷新JVM缓存。
